# PF2E Eliott Tools

Личный модуль для Pathfinder 2e в Foundry VTT: небольшие фиксы, автоматизация и готовые компендиумы для наших игр.

## Что делает модуль

- Добавляет бестиарий группы: отдельные записи существ, поиск, раскрытие сведений мастером и общие заметки игроков.
- Исправляет `Oath of the Defender`: сопротивление союзников в ауре применяется только к самому большому подходящему инстансу урона, как написано в фите.
- Исправляет учёт владения группой оружия для `Weapon Familiarity`: например, продвинутый орочий топор получает мастера при мастерском владении воинскими топорами.
- Добавляет готовый компендиум `Hero Action Deck` с картами действий героя.
- Добавляет русский компендиум `Critical Hit/Fumble Deck RU` и перенаправляет броски стандартной крит-колоды PF2e на русские записи журнала.
- Добавляет опциональную автоматизацию `Shields of the Spirit`: когда атакующее действие с признаком `attack` направлено на цель с этим эффектом, модуль автоматически бросает ответный spirit-урон по атакующему.
- Добавляет боевые улучшения: автосброс целей при смене хода и круговой HP-индикатор в боевом трекере.
- Добавляет мастеру кнопку ▶/⏸ в стандартное окно PF2e «Время мира»: одна игровая секунда за одну реальную.
- Автоматически накладывает тошноту 1 при критическом промахе безоружной атакой по доспеху из холодного железа, серебра или суверенной стали, если у атакующего есть нужная уязвимость.

## Бестиарий группы — первая версия

Обновите страницу Foundry у мастера и игроков. Откройте **Акторы → Бестиарий группы**, **Журналы → Бестиарий группы** или нажмите **Shift+B** вне текстового поля. Окно также доступно в настройках модуля. При обновлении на запущенном сервере новые скрипты и стили подгружаются автоматически; перезапуск сервера не обязателен.

1. Нажмите **Добавить существо** и выберите NPC из мира, либо перетащите актора из списка/компендиума в окно. Кнопка **Из выбранных токенов** добавляет выделенных на сцене NPC.
2. Имя существа всегда видно группе, в том числе после **Скрыть всё**. В новой записи также открыт портрет; прочие сведения скрыты.
3. Кнопки **Скрыто / Открыто** управляют отдельными характеристиками, атаками и способностями. Каждый признак, чувство, вид скорости и язык раскрывается отдельно. У чувств сохраняются дальность и точность. Особенности скорости и языков — отдельные пункты. Если признаков, чувств, скоростей, языков, слабостей, сопротивлений или иммунитетов нет, мастер может отдельно раскрыть **Нет**. Пока пункт скрыт, игроки не узнают об отсутствии. Можно раскрыть раздел целиком. **Глазами игрока** показывает только опубликованные сведения.
   Признаки, чувства, скорости, языки, слабости, сопротивления и иммунитеты собраны в общие блоки со списком: одна строка на пункт и своя кнопка раскрытия. Игрокам показываются только открытые строки.
   Заклинания показаны компактно: **стрелка, внутренняя ссылка с названием и ранг**. Стрелка разворачивает и сворачивает сохранённое описание прямо в карточке. Нажатие на название отдельно открывает оригинальный лист заклинания из компендиума внутри Foundry, со штатным оформлением и ссылками на состояния и эффекты. Если оригинал недоступен, небольшое окно показывает сохранённое описание. Ранг в бестиарии относится к существу; оригинал может иметь меньший базовый ранг. КС заклинателя в списке не выводится. В сохранённых описаниях вставки `@Unit` и `@Condition` показывают читаемые подписи.
   Если локализация добавляет исходный текст, он показывается отдельно под свёрнутым блоком **Оригинал**. Перевод остаётся основным описанием. Уже сохранённые карточки со склеенным заголовком «Оригинал» распознаются при отображении; повторное добавление существа не требуется.
4. **Заметки группы** редактируются мастером и игроками; текст сохраняется кнопкой. Черновик сохраняется при переключении карточек, а закрытие окна предупреждает о несохранённых заметках. Если уже пришло чужое изменение заметок, сохранение предупреждает о конфликте; одновременное сохранение двумя участниками ещё требует ручной координации.
5. Повторное добавление из одного источника открывает существующую запись. Галочка **Как отдельную запись** создаёт независимый вариант. Элитные и ослабленные варианты учитываются отдельно. Разные домашние акторы без общего источника считаются разными существами, даже если имена совпадают.
6. **Обновить из источника** заменяет снимок характеристик, сохраняя заметки. Изменившиеся сведения снова скрываются, имя остаётся открытым. Если исходник удалён, запись остаётся доступна; обновить её из отсутствующего источника нельзя.
7. **Удалить запись** в действиях карточки удаляет только выбранное существо из бестиария вместе с его раскрытыми сведениями и заметками. Подтверждение содержит имя существа. Другие карточки и исходный актор сохраняются. Несохранённые заметки удалённой карточки также очищаются.
8. **Очистить всё** в шапке бестиария удаляет все его карточки и заметки после отдельного подтверждения. Та же операция доступна через макрос **Бестиарий — сброс данных**, который автоматически появляется после входа основного GM, или через `await game.modules.get("pf2e-eliott-tools").api.bestiary.reset()`. Акторы, токены, компендиумы и остальные журналы не затрагиваются. Пустые папки остаются. Отмена сохраняет данные. Обе кнопки доступны только мастеру и скрыты в предпросмотре игрока.

Записи хранятся в обычных документах мира: папка журналов **Бестиарий · данные мастера** содержит снимки с правами только мастера, **Бестиарий группы** — опубликованные карточки и страницу общих заметок. Исходные акторы не изменяются. Не удаляйте эти папки, если хотите сохранить бестиарий. Он входит в резервную копию мира; код модуля не содержит знаний конкретной группы. Отключение модуля не удаляет записи. Это стандартная модель разрешений Foundry, а не шифрование данных от клиентов.

Первая версия поддерживает существ/NPC PF2e, точные значения, атаки, способности, заклинания и описание обычным текстом. Она снимает характеристики в текущем состоянии актора; временные модификаторы могут попасть в снимок. Пока нет опасностей, импорта из Bestiary Tracking, автоматического раскрытия из боя, приблизительных значений и объединения записей. При нескольких мастерах изменения выполняет основной активный GM. Ссылки на изображения сохраняются, сами файлы не копируются.

Проверка: добавить одного NPC дважды (одна запись), раскрыть КБ и один из нескольких признаков, проверить вид игрока, сохранить заметку, обновить браузер и убедиться, что знания и заметка остались. Имя видно сразу; остальные признаки должны остаться скрытыми. Проверьте раскрытие **Нет** для пустых языков и иммунитетов. Для проверки независимости от источника используйте отдельного временного NPC.

Ранее проверено в локальном Foundry v14 с PF2e 8.5.0: открытие с закешированным манифестом, добавление через список, повторное добавление, раскрытие КБ, предпросмотр, обновление из источника, запись заметок под GM и Player2, сохранение после перезагрузки. Дополнительно проверены русские описания `@Localize`, старые признаки мировоззрения, значки заголовка, выравнивание списка и открытие заклинания из компактной строки. Автоматические проверки бестиария: `node --test tests/bestiary.test.cjs` (29 тестов), включая разделение перевода и оригинала, отдельные раскрытия, миграцию списков, постоянное имя, отсутствие данных, ссылки и разворачивание заклинаний, удаление одной записи и общий сброс с подтверждением. Удаление проверяется только на тестовых документах. Новые блоки оригинального текста, кнопки удаления, отдельные раскрытия и макрос требуют проверки в игровом интерфейсе после перезагрузки GM. Перетаскивание, добавление выделенных токенов и версии Foundry v12/v13 также требуют дополнительной ручной проверки.

После обновления достаточно перезагрузить страницы мастера и игроков. При подключении основного GM старые списки признаков, чувств и скоростей автоматически разделяются, сохраняя раскрытие каждого прежнего списка. Пустые списки получают скрытое **Нет**. Языки, которых раньше не было в снимках, добавляются из доступного источника скрытыми; если источник удалён, карточка честно сообщает, что языки не сохранены. Другие характеристики не обновляются. Сохранённые заклинания переходят на компактный формат. Заметки и раскрытые заклинания сохраняются. Ссылки локализации в описаниях раскрываются при показе карточки на языке текущего клиента.

## Уменьшение испуга в конце хода

Настройки модуля → «Автоматизация листа персонажа» → «Автоматически уменьшать испуг в конце хода». Галочка включена по умолчанию, изменение действует сразу для всего мира.

По [правилу Frightened](https://2e.aonprd.com/Conditions.aspx?ID=19) значение испуга уменьшается на 1 в конце каждого собственного хода, если не указано иное. Модуль использует событие `pf2e.endTurn`: испуг 3 → 2 → 1 → снятие. Работает для персонажей и NPC в запущенном бою, в том числе отдельных акторов несвязанных токенов. Вне боя таймеров нет; простое изменение инициативы не запускает уменьшение. Обрабатывает только активный GM. Повтор события того же завершённого хода не уменьшает состояние ещё раз; перемотка назад не восстанавливает снятый испуг.

Используется штатное уменьшение состояния PF2e. Независимые источники испуга уменьшаются каждый отдельно, включая перекрытые более сильным источником. Закреплённые, доступные только для чтения и создаваемые в памяти состояния пропускаются: ими управляет исходный эффект. Текстовые запреты без автоматизации в системе (например, `Remorseless Lash`) требуют ручного контроля — временно отключите эту функцию и примените нужный минимум вручную. Не включайте её вместе с аналогичной автоматизацией другого модуля.

Для проверки добавьте участнику боя испуг 2. Завершите его ход: должно остаться 1. После следующего его хода состояние должно исчезнуть. Завершение чужого хода не уменьшает его испуг. С выключенной галочкой модуль значение не меняет. После установки скрипта один раз обновите страницы участников.

## Знакомство с оружием и владение группой

Настройки модуля → «Автоматизация листа персонажа» → «Включить фикс Weapon Familiarity». Включён по умолчанию для всего мира; изменение настройки требует перезагрузки страницы у участников.

Обход для [PF2e #18632](https://github.com/foundryvtt/pf2e/issues/18632) и [#16906](https://github.com/foundryvtt/pf2e/issues/16906): активные правила `MartialProficiency` у фитов со slug `*-weapon-familiarity` учитывают не только общий ранг категории, но и более высокий ранг подходящей группы оружия. Работает с `Orc Weapon Familiarity` и аналогичными фитами родословной, использующими такие же правила. Мастерство и легендарное владение берутся из текущих способностей персонажа, а не задаются фиксированным бонусом +2.

Категория, группа и признаки предметов не редактируются. Дополнительные владения рассчитываются в памяти до подготовки Ударов; сохраняются ограничения по признакам, группе и максимальному рангу. Продвинутое оружие не получает владение простым через цепочку двух правил знакомства. Расчёт выполняется при обычной подготовке персонажа, без таймеров, записей в базу и сканирования сцены. Фикс не распространяется на другие фиты вроде `Advanced Weapon Training` и не заменяет все ограничения системы владения оружием.

Проверка на персонаже со скриншотов:

1. Обновить страницу после установки изменений. Вернуть потрошающему топору категорию «Продвинутое оружие» и убрать добавленные вручную обходы владения.
2. Убедиться, что есть `Orc Weapon Familiarity`, а в `Fighter Weapon Mastery` выбраны топоры.
3. При уровне 9 и Силе +4 без дополнительных бонусов Удар должен показывать «Мастер», владение +15 и итог +19. Другой продвинутый топор без признака «орк» остаётся на эксперте.
4. Отключить фикс и перезагрузить страницу: до официального исправления PF2e тот же орочий топор снова использует эксперта, итог +17. Старые сообщения в чате не пересчитываются; сделать новый бросок.

## Материалы доспехов и критические промахи

В настройках модуля → «Автоматизация листа персонажа» есть галочка «Включить эффекты материалов доспеха при критическом промахе» (включена по умолчанию, действует сразу для всего мира).

| Материал надетого доспеха | Уязвимость атакующего | Результат критического промаха безоружной атакой |
| --- | --- | --- |
| [Холодное железо](https://2e.aonprd.com/Equipment.aspx?ID=2798) | Холодное железо | Тошнота 1 |
| [Серебро](https://2e.aonprd.com/Equipment.aspx?ID=2803) | Серебро | Тошнота 1 |
| [Суверенная сталь](https://2e.aonprd.com/Equipment.aspx?ID=777) | Холодное железо | Тошнота 1 |

Материал должен быть выбран в поле материала самого надетого доспеха, а у атакующего — указана уязвимость в листе. Название предмета, признак «нечестивый», тип «демон» или исключение из сопротивления не заменяют уязвимость. Перед броском нужно выбрать цель, чтобы PF2e сохранил её и степень успеха в сообщении атаки. Учитывается итоговая степень успеха, а не только натуральная 1. Работает с безоружными Ударами персонажей и NPC, включая когти и укусы с признаком `unarmed`.

Все степени качества материала дают именно тошноту 1. Повторные промахи не складывают её и не уменьшают уже имеющуюся тошноту 2+. Используется штатное состояние PF2e с проверкой иммунитета. В чат отправляется сообщение с материалом, атакующим, целью и результатом: тошнота наложена, уже имеется или не наложена из-за иммунитета. Сообщение сохраняет аудиторию исходного броска, включая приватные и слепые броски, и содержит ссылку на правило. Эффект обрабатывает только активный GM, без таймеров и сканирования сцены. При отключении функции уже наложенная тошнота остаётся до обычного снятия.

Это автоматизация конкретного триггера критического промаха, а не всех свойств материалов: ношение вредного доспеха самим уязвимым существом, ауры абизия и урон сиккатита при захвате сюда не входят. У остальных материалов нет автоматически добавленного эффекта на такой промах. [Рассветное серебро (dawnsilver, прежний mithral)](https://2e.aonprd.com/Equipment.aspx?ID=2917) приравнено к серебру для урона; перенос тошноты на него неоднозначен, поэтому он не включён в автоматизацию.

После переброса, отменившего исходный критический промах, уже наложенную тошноту при необходимости снимает мастер: автоматизация не откатывает ранее применённые состояния.

Для проверки используйте копии существ на тестовой сцене:

1. Включите настройку автоматизации и обновите страницу после установки изменений.
2. Наденьте на защитника доспех с материалом «Серебро» (`silver`). На листе атакующего добавьте уязвимость «Серебро», например 5; убедитесь, что у него нет тошноты и иммунитета к ней.
3. Выберите защитника целью и сделайте по нему Удар кулаком, когтями или укусом с признаком «Безоружное» (`unarmed`). Для быстрого получения критического промаха можно добавить большой временный штраф к броску в диалоге, например −100. Проверьте именно итог «Критический провал»: натуральная 20 может повысить его до обычного провала.
4. У атакующего должна появиться тошнота 1, а в чате — объяснение с материалом «Серебро».
5. Снимите тошноту, смените материал надетого доспеха на «Суверенная сталь» (`sovereign-steel`, стандартное качество), а уязвимость атакующего — на «Холодное железо». Повторите атаку: результат тот же, в чате указана суверенная сталь.
6. Проверьте отсутствие эффекта при обычном промахе, оружейной атаке, снятом доспехе, удалённой уязвимости и выключенной настройке. При иммунитете или уже имеющейся тошноте 2 чат объясняет отсутствие нового состояния, а её значение не меняется.

## Автоматический ход времени

Откройте «Время мира» и нажмите «Запустить время». Кнопка «Пауза» останавливает отсчёт. Закрытие окна не останавливает часы; ручные кнопки продвижения времени работают как обычно.

В настройках модуля, в разделе «Время мира», мастер может отключить «Автоматический ход времени». Кнопка сразу исчезает, таймер останавливается. Повторное включение возвращает кнопку и прежнее состояние запуска, без добавления времени, прошедшего при отключённой функции.

На паузе Foundry и пока есть начатый бой автоматический отсчёт приостанавливается и возобновляется после снятия паузы/завершения боя. Состояние запуска общее для всех мастеров и сохраняется при перезагрузке. Время продвигает только один активный мастер; без подключённого мастера часы не идут и пропущенное время при подключении не добавляется.

Меняется настоящее время мира Foundry, поэтому PF2e обрабатывает длительности эффектов и синхронизацию освещения так же, как при ручном продвижении времени.

## Настройки

В стандартных настройках модуля можно отдельно включать и выключать:

- фикс `Oath of the Defender`;
- фикс владения оружием для `Weapon Familiarity`;
- уменьшение испуга на 1 в конце собственного хода;
- русский оверрайд крит-колоды;
- автоматизацию `Shields of the Spirit`.
- автосброс целей в конце хода;
- HP-кольцо в боевом трекере.
- автоматический ход времени мира.
- эффекты материалов доспеха при критическом промахе.

Это нужно, чтобы быстро отключить функционал, если PF2e позже добавит официальную поддержку или если конкретная игра хочет вести правило вручную.

Настройки разделены заголовками по категориям. Автосброс целей клиентский: каждый игрок может отключить его у себя, но по умолчанию он включен для всех. HP-кольцо настраивается мастером для мира.

## Важное замечание о переводе

Русский текст `Critical Hit/Fumble Deck RU` переведен через ИИ и должен быть проверен мастером перед использованием.

## Релиз

Для публикации новой версии:

1. Обновить `version` в `module.json`.
2. Закоммитить изменения и отправить их в GitHub.
3. Создать и отправить тег вида `vX.Y.Z`, например `v0.3.0`.
4. GitHub Actions соберет `module.json` и `pf2e-eliott-tools.zip`, затем опубликует release.

В pack-папках в git должны оставаться только данные готовых компендиумов:

```text
packs/*/*.ldb
packs/*/CURRENT
packs/*/MANIFEST-*
```

Временные файлы Foundry/LevelDB не нужны в репозитории:

```text
packs/*/LOCK
packs/*/LOG
packs/*/LOG.old
packs/*/*.log
```

`CURRENT` и `MANIFEST-*` — обязательные части базы, а не временные логи. Foundry может менять их при открытии мира даже без редактирования содержимого. Такие изменения не нужно добавлять в коммит с изменениями кода. При обновлении самих компендиумов сохраняйте согласованный снимок всей базы после закрытия мира; не откатывайте отдельные файлы открытой базы.

Текущая сборка релиза упаковывает `packs/` прямо из Git. Исключать `CURRENT` и `MANIFEST-*` из репозитория по отдельности нельзя. Чтобы убрать этот шум полностью, нужно перейти на JSON/YAML-исходники обоих компендиумов и сборку LevelDB при выпуске релиза — [рекомендованный Foundry подход](https://foundryvtt.com/article/v11-leveldb-packs/).
